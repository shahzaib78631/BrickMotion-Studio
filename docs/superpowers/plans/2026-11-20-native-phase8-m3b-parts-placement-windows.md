# Native Phase 8, Milestone 3b — Parts, placement, and app windows

**Status (2026-11-20)** — M3b implementation is in the local workspace. Its editor flows now run through the Parts navigator, viewport, command registry and document history. Milestone 4 integration and Phase 8 sign-off are in progress.

**Implementation** — Parts has Common, Frequent and Recent, category and exact-ID search, colour, orientation, mirroring and optional placement examples. The navigator, inspector and replacement picker share offscreen Metal previews. Placement uses the active model’s free mating connectors, stable grip selection and collision checks. Library activation and direct dragging show the same preview. Committing creates one named undo step, including an edit inside a shared model. The viewport and inspector describe blocked poses.

**Connections and windows** — The selection bar and menus expose group tags, fit alternatives, geometric touching and the connection graph. The joint card can turn or release an eligible branch after clearance checks. Import Into adds a named submodel and its definitions in one undo step. Welcome uses system recents and rendered project thumbnails. Settings persists appearance, viewport options and Auto Plan.

**Verification** — The 10030 ×4 placement benchmark measured 4.59 ms at p95 for candidate queries and 454 ms for the initial spatial index, which runs off the main thread. The native placement self-test drives Return and mouse dragging, undo and redo, focus changes and stale requests. Reviewed dark and light editor captures and exercised Welcome, Open, Settings and planner diagnostics through the running Mac app’s accessibility tree.

**Outcome** — Find a part in the library, recognize it by shape, choose its colour, and place it into the active model with a clear preview and one undo step. Make connections and blocked poses understandable at the point of editing, and make opening and configuring the app feel as deliberate as editing a model.

## Interaction and visual acceptance

- **Parts** — A pinned search and category control leads into a resizable grid of real part renders. Keep the same isometric view, optical scale, and framing from tile to tile. At a 220 pt sidebar width the grid, part names, and part numbers remain useful. Exact part numbers rank first. Empty search starts with Frequent, Common, and Recent as data becomes available. Distinguish loading, a missing library, an empty collection, and a query with no matches. Keep search and scroll position stable while switching tabs or changing colour.
- **Placement** — The viewport shows a legible translucent part and its active grip. A snap targets a stable connector until the pointer leaves its release radius. A refused pose has a different outline, an icon, and a plain-language reason that also appears in the inspector. Use a compact glass control strip for the controls relevant to the current gesture. Return or click commits, Tab cycles grips, R turns, Option bypasses snapping, and Esc cancels. The same rules apply after starting with pointer, keyboard, or drag. Orbit and pan stay available and never commit a placement.
- **Editor feedback** — Let users read the selected part, the connection, and the next action in that order. Keep the selection bar clear of the pointer and viewport edges. Use macOS materials on floating controls, SF Symbols with labels or help, and the system accent for active selection. Keep focus visible. Honour increased contrast, Reduce Motion, and keyboard navigation in both appearances. Save space by removing idle status copy once the viewport or control already communicates the state.
- **App entry** — Welcome has a clear Open and New, with recognizable thumbnails and file locations for recents. It follows the system document lifecycle, including Finder opens and restored windows. Settings groups real controls by Appearance, Viewport, and Planning. Use native file panels and window shortcuts.

## Implementation sequence

1. **Parts library browsing and thumbnail proof.** Reuse `Session::searchParts` ranking through a catalog API that can browse by category and work in untitled documents. Read LDraw category metadata with a description fallback. Build the Parts navigator with a compact adaptive grid, Common parts, exact-ID search and category filtering. Prove that a worker-owned Metal renderer can render and read back a part while the editor's renderer is alive. Give offscreen work its own library/cache and keep catalog file I/O and thumbnail readback off the main actor. Request previews only for visible tiles, bound the memory cache, and use a versioned disk cache keyed by library, part and render settings. Reuse the same preview path in the inspector once it is proven.
2. **Headless placement and snapping.** Add pure C++ candidate generation around world rays using `ConnectorDb`, mating frames and collision queries. Measure the free-connector index on 10030 ×4 before choosing its invalidation strategy. Key it to document generation, edit version and focus. Use connector identity to resolve ties deterministically; exclude moving pieces from their own targets. Represent a free pose, snapped pose, and refusal explicitly. Separate preview from commit, reject stale candidates, and test occupied connectors, permitted engagement, blocking crossings, mirror transforms and coordinates inside submodels.
3. **Place parts through the real editor.** Add a focused-model edit command that commits one part, or one moved selection, with undo and redo. Wire tile activation, drag-and-drop, new-part colour and Use This Colour through the same placement state. Add Frequent and Recent from committed placements, plus initial orientation, placement hint and mirror controls. A ghost stays outside the model and document history until commit. Exercise focus changes, document switches, cancellation, lost drag, and failed edits. Extend the same gesture to placed pieces and verify the resulting file with the web reader.
4. **Connections, checks, and selection tools.** Expose joint and collision details through snapshots. Add joints, aim and collision tools, a joint card, and a floating selection bar using the command registry. Add Fit Together and ranked ways to fit, Select Connected from the connector graph and Select Touching from geometry, and undoable Group with tags in the inspector and model tree. Wire Import Into to the focused model with a single undo step and conflict-safe ID and definition remapping. Cover refused edits in the viewport and Part inspector.
5. **Settings, Welcome, and About.** Add system/light/dark appearance, supported viewport preferences and the auto-plan preference. Apply changes to open and future windows. Wire Welcome to `NSDocumentController` recents, prior window restoration, Open, and a real blank project via New. Render recent thumbnails asynchronously, including meaningful loading and unavailable states. Add an About window with build and engine versions and credits.
6. **Parity and interaction sign-off.** Update the parity ledger and `native/README.md` with completed rows, measurements and outstanding checks. What Fits previews and placement are available from a part. The timeline Parts lane, staged layout, build playback and animation editing are tracked in the M4/M5 plan. Library updates and the advanced export panel follow in Phase 9.

## Verification gates

- Run targeted catalog, snap, edit and export regressions as each slice lands, then run both CTest trees. Drive placement through the real viewport, including pointer and keyboard input, and verify save, reopen, undo and redo in the focused model.
- Capture actual windows in light and dark at 900 × 600 and 1440 × 900. Review Found/No Results, a loaded and missing thumbnail, free/snapped/refused poses, keyboard focus, and Welcome with and without recents. Check the editor at a 220 pt sidebar and with both sidebar and inspector visible.
- Record cold catalog and preview readiness, warm search and thumbnail latency, index rebuild time, and pointer-to-preview latency on the reference Mac. Target warm search under 50 ms and candidate queries within one 120 Hz frame on the reference model. Measure use of CPU time on the main thread separately from rendering and cache I/O.

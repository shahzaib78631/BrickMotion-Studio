# Standard Motion v3 — Mechanics & Kinematics Upgrade

**Scope:** Adds true one-degree-of-freedom motion to connector-guided *assembly approaches*. Builds remain editable previews; this is **not** rigid-body dynamics, full inverse kinematics, gear/linkage simulation, or mesh collision certification.

## What was wrong

Before this upgrade, a hinge/clip/ball-joint route stored a list of rotated world matrices in `posePath`. Playback interpolated position and orientation *separately* between every pair of matrices. The resulting path was a straight chord of the desired arc. Even if the two matrices put the hinge pin at its correct pivot, the animated joint centre could move between them and clip through the host or other pieces. Likewise, the old insertion candidate could add an arbitrary pin/cylinder twist.

## What now happens

1. **Joint-space revolute kinematics:** A connector-derived hinge/clip is moved about its *fixed world-space pivot and axis* during the seated/swinging phase of assembly. Ball/socket connections use a local tangent rotation about the ball centre. Every subframe is generated by the rigid transform `T(pivot) · R(axis, angle) · T(-pivot) · starting_pose`. Translation and orientation are no longer independently lerped during those constrained segments. The chosen final pose is still the exact source LDraw matrix.
2. **Prismatic kinematics:** For pin/hole, axle/hole, stud/socket and cylinder insertions, the last phase moves strictly along the inferred connector axis. No fictional screw-turn is applied to pins, and keyed axles and studs do not rotate as they seat. The approach direction is still evaluated for obstruction by the existing time-aware route scorer.
3. **Mechanism mobility filtering:** A hinge cannot be swung if another *already installed* mating connector would immobilize it. Multiple hinge barrels must be nearly parallel/coaxial. An axial insertion may share multiple parallel stud/pin connections; a crossing axis locks that proposal. Multiple distinct ball centres also block an unconstrained ball swing. If metadata is missing or conflicted, the engine falls back to ordinary editable motion rather than inventing a kinematic solution.
4. **Collision review includes real trajectories:** The existing v3 installed/staging/concurrent-flight AABB scorer now samples exact pivot arcs more densely and indexes intermediate arc poses as well as waypoints. Its route diagnostics are based on the generated poses that preview/export actually use. These bounds are still *advisory* and may contain false positives or miss narrow mesh contacts.
5. **Worker, keyframes and UI:** The new `kinematicSegments` descriptors are pure serializable timeline data, so Build preview, saved/reloaded worker timelines and native frame baking evaluate the same procedural path. Video and Build show counts for exact-pivot swings, axial insertions and mobility-locked hints. Cache version `standard-motion:kinematic-constraints-v3-r3` avoids reusing old chord-interpolated plans.

## How to use it

1. Open **Video → Planner → Standard Motion v3 — mechanics + kinematics (editable preview)**.
2. **Regenerate Build**. The source model is not modified. Look at the joint-kinematics counts in Video/Build and review remaining route warnings in **Timeline → Review routes**.
3. Click **Edit all part keyframes** to auto-generate editable per-brick channels. Existing manual channels are never overwritten by automatic fill. If you already have baked flight tracks and want the new joint-space motion, back up corrections and use **Rebake all**. Then run **Check motion** on the edited result.
4. Save/export normally. No new project fields are required. Missing connector metadata is tolerated, but cannot enable unsupported joints.

## Guarantees and non-goals

- Rotations on a selected revolute segment exactly preserve its inferred *world joint pivot*, including between waypoints, without changing rigid shape, reflection or shear. Axial motions are exact translations along their inferred world axis.
- **Not certified:** A matched connector alone cannot establish hinge clearance, actual allowed angular range, spring/friction/mass behaviour, stability, gear meshing, multi-link constraints or flexible-part deformation. Angle amounts are conservative preview proposals, **not physical joint limits**.
- **Only free single-leaf main-assembly motions** receive inferred joint-space approaches. Multi-leaf rigid attaches and temporary workbench moves retain the existing Standard paths, avoiding mismatched final-world pivots.
- Baked native keyframes reproduce the procedural samples at the chosen frames, but independent Location/Rotation channels cannot enforce a live joint constraint *after manual edits* or for arbitrary in-between frames. Run Check motion after edits, especially on long linkages. AABB clearance is not a triangle-mesh certificate.
- If the route scorer finds no clear alternative, the least-obstructed preview is retained with a review warning rather than silently teleporting or moving other pieces. Final authored placement is unchanged.

## Relevant code

- `src/anim/motion/jointKinematics.ts`: world-space forward kinematics and mobility compatibility.
- `src/anim/motion/kinematicCandidates.ts`: hinge, clip, ball and insertion proposals plus joint-segment metadata.
- `src/anim/timelineData.ts`, `src/anim/timeline.ts`, `src/anim/timelineCodec.ts`: joint-space timeline representation, playback and worker codec.
- `src/anim/motion/standardMotion.ts`: constraint-filtered selection and kinematic summary.
- `src/anim/motion/routeSelection.ts`: time-aware AABB review sampling real joint arcs.
- `src/state/timelineService.ts`, `src/ui/VideoPanel.tsx`, `src/ui/BuildTimeline.tsx`: cache and UI descriptions.
- `tests/anim/standardMotionKinematics.test.ts`, `tests/anim/standardMotionJoints.test.ts`: regression tests.

### Validation

With dependencies installed, run:

```bash
npm run typecheck
npm test -- tests/anim/standardMotionKinematics.test.ts tests/anim/standardMotionJoints.test.ts tests/anim/standardMotionRoutes.test.ts tests/anim/standardMotion.test.ts
npm run build
```

For this delivery, package installation could not be completed in the isolated runtime, so the full application typecheck, Vitest suite and browser build were **not** run. Focused independent numeric checks passed for fixed-pivot motion, axial insertion, overconstrained mates, reflected/sheared transforms and exact endpoints; the pre-existing offline route-regression harness also passed for concurrent motion, staging occupancy, high obstacles, host tunnelling and late contact. Edited TypeScript/TSX source passed syntax transpilation. This is valuable smoke coverage, not a production integration sign-off.
